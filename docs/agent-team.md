# 프로젝트 전담 에이전트 운영

총괄(root)은 요구사항·API 계약·작업 범위를 조율하고 최종 통합 검수와 커밋을 담당한다. 기본 모델은 Luna 최고 추론 수준이며, 복잡한 설계가 필요할 때만 상위 모델을 사용한다.

| 역할 이름 | 책임 | 완료 조건 |
|---|---|---|
| frontend_builder | 프론트 구현·수정 | 수정 파일·변경 동작·검증 결과를 전달 |
| frontend_reviewer | 프론트 독립 검수 | 재현 조건과 근거를 제시하고 수정본 재검수 |
| backend_builder | 백엔드 구현·수정 | API·권한·저장 규약 및 변경 영향을 전달 |
| backend_reviewer | 백엔드 독립 검수 | 계약·권한·오류·데이터 일관성 확인 |
| test_engineer | 자동 테스트 작성·실행 | 성공 경로와 실패·회귀 조건을 실행 가능한 테스트로 확인 |
| qa_engineer | 통합 인수 검수 | 실제 사용자 흐름·설치법·테스트 주장과 증거 대조 |

- 기존 역할 에이전트를 재사용한다. 세션에서 에이전트를 찾을 수 없을 때만 같은 역할로 다시 생성한다.
- 동시 실행은 총괄 포함 4개 제한 안에서 순차 배치한다. 검수 완료 담당은 대기하고 제작 담당을 가동한다.
- 제작자와 검수자는 분리한다. 테스트 담당은 앱 코드를 임의 수정하지 않고 실패를 제작자에게 전달한다.
- 공유 작업 폴더에서는 파일 소유 범위를 먼저 지정한다. 제작자의 편집 완료 알림 전에는 중간 파일 상태를 실패로 보고하지 않는다.
- 인수인계는 `대상 커밋/파일 → 변경 또는 재현 조건 → 실행 명령/결과 → 미검증 범위` 순서로 총괄에게 전달한다. 담당자 간 직접 메시지가 불가능하면 총괄이 전달한다.
- 연결 성공, 이벤트 전달, 화면 표시, 재연결은 서로 다른 검증이다. 하나를 통과했다고 나머지도 통과했다고 기록하지 않는다.
- 수정 후 분야별 재검수와 통합 QA를 거친다. 총괄이 실제 결과를 확인한 뒤 작업 파일만 커밋한다.
- 인프라 작업이 필요할 때 `infra_builder`/`infra_reviewer`를 같은 방식으로 추가한다. 이번 검수에서는 CI/CD·Notion 설정을 변경하지 않는다.
