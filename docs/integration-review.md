# 통합 재검수 — 2026-09-23

이슈 #1의 통합 결과를 분야별 제작자·검수자, 테스트 담당, QA 담당, 총괄이 재검수했다. 이전 빌드·테스트 통과는 전체 동작의 무결함을 의미하지 않았다. 아래는 이번에 재현한 문제와 수정 범위다.

| 문제 | 수정 및 확인 |
|---|---|
| 삭제·강등된 계정의 기존 JWT가 관리자 API에 계속 접근 | 요청마다 현재 계정을 확인. 총괄 로컬 재현에서 강등 후 관리자 조회가 200 → 401로 변경 |
| 열린 SSE가 인증 만료·계정 변경 이후에도 이벤트를 받을 수 있음 | 만료 시 연결 종료, 전달 직전 계정·역할 재검사. 회귀 테스트로 전달 차단 확인 |
| 숫자 이메일 등 잘못된 사용자 수정 입력이 500 발생 | 필드 검증 후 400 반환. 총괄 로컬 재현에서 숫자 이메일이 500 → 400 |
| 동시에 같은 이메일로 수정하면 중복 계정 가능 | 단일 백엔드의 저장 작업 안에서 정규화된 이메일 중복 검사 |
| 로그아웃 버튼이 ‘역할 변경’으로 표시 | ‘로그아웃’으로 수정. 총괄 브라우저 확인 |
| 정상 SSE도 첫 이벤트 전까지 ‘연결 중’ 표시 | 응답 검증 직후 연결됨 처리. 이벤트 없는 상태에서도 브라우저 확인 |
| 일시적 서버 장애 시 로그인 복원 실패가 토큰 삭제로 이어짐 | 인증 거절과 통신 장애를 구분. 서버 복구 후 비밀번호 재입력 없이 다시 확인으로 복원 |
| 자동 재연결 소진 후 복구 버튼 없음 | ‘다시 연결’ 추가. 독립 재검수에서 발견한 기록 초기화 부작용도 보완 |
| SSE 테스트가 연결 응답만 확인 | 실제 입력 → 이벤트 전달·필드 검증과 만료·권한 변경 시 전달 차단 테스트 추가 |
| 서로 다른 포트의 개발 실행에 필요한 API 주소 안내 누락 | `server/README.md`에 Vite 시작/빌드 전 API origin 설정 안내 |

## 팀 운영에서 보완한 점

- 제작자 자신의 빌드 성공만으로 완료하지 않는다. 분야별 검수자가 별도로 확인한다.
- 테스트 담당은 앱 코드와 분리해 회귀 조건을 작성하고, QA는 주장한 검증과 실제 테스트를 대조한다.
- 총괄이 브라우저·로컬 API에서 주요 문제를 직접 재현하고 수정 후 결과를 비교했다.
- 파일 소유 범위를 나누고, 작업 완료 알림 이후에 검증한다. 편집 도중 일시적으로 삭제된 파일은 실패로 보고하지 않는다.
- 동시 실행 한도 때문에 역할을 순차 가동한다. 재가동 실패가 발생하면 동일 역할을 재요청하며, 실제 실행되지 않은 검수는 통과로 처리하지 않는다.
- 역할과 인수인계 기준은 [agent-team.md](agent-team.md)에 유지한다.

## 유지되는 범위와 제한

- 고객 데이터·외부 API·GPU·메일은 사용하지 않았다. 임시 계정과 로컬 테스트 서버만 사용했다.
- JSON 계정 저장은 단일 백엔드 전제다. 비밀번호 변경만으로 기존 JWT를 취소하는 기능은 아직 없다.
- 실제 모델, 미구현 목록·상세 API, 배포·CI/CD·Notion 연동은 이번 결함 수정 범위에 포함하지 않는다.
- SSE 유실 재전송은 제공하지 않는다. 연결 복구가 과거 이벤트 복구를 보장하지 않는다.
- 최종 자동 테스트 결과는 [validation.md](validation.md)에 기록한다.
