# KSJ·HUJ 통합 커밋 계획

상태: C1~C6 구현·검증 완료. C6에는 재실행 가능한 테스트와 서버 단독 실행 검증 결과를 포함한다. 작업 브랜치는 `feat/1-ksj-huj-integration`이고, 기준은 `import/legacy-layout`의 `2be5a51`, 병합 대상은 `legacy/HUJ`의 `5987bc4`다.
Issue: [#1](https://github.com/kohs2k21/2026-2-CECD2-1-POWERCODE-03/issues/1) 사용자 답변 원문은 `merge-decisions.md`에 유지한다.

## 확정한 방향

- KSJ 화면·컴포넌트 구조 유지, HUJ에서 필요한 기능만 이식.
- API 우선. 미구현 기능에만 명시적 목업을 사용하고 목록으로 관리. API 실패·빈 응답을 목업으로 대체하지 않음.
- 현재 존재하는 API만 연결. 실제 항목의 미제공 필드는 미제공으로 표시.
- 로그인 필수, 사전 생성 테스트 계정만 사용. 회원가입과 가입용 인증코드 API 비활성화. 가입용 SMTP 연결은 보류.
- 누락 타입을 보완하고 JSON 사용자 저장 유지. 백엔드 단일 인스턴스와 영구 저장 경로를 기준으로 함.
- 배포 대상은 server/만. Actions·Notion 설정·배포·브랜치 삭제는 이번 범위 밖.

## 구현 상태

| 순서 | 범위 | 해당 커밋에서 확인할 것 |
|---|---|---|
| 1 | 결정 사항과 목업 목록 작성 | UI뿐 아니라 서버 예시 입력·임시 계산도 빠짐없이 식별 |
| 2 | HUJ 이력을 병합하고 server/ 경로·빌드 정리 | KSJ 화면 보존, 중복 앱 폴더 없음, 양쪽 빌드·이력 확인 |
| 3 | 사전 계정 로그인과 서버 권한 확정 | 비로그인 거부, 일반/관리자 구분, 가입·인증코드 차단, 재시작 후 계정 유지 |
| 4 | 프론트 로그인과 기존 HTTP API 연결 | 로그인 복원·로그아웃, 실제 API 오류, 목업 표시·교체 경계 |
| 5 | 인증된 SSE와 분석 화면 연결 | 재연결·중복·연결 종료, 불완전한 상세 데이터, 목업과 실데이터 분리 |
| 6 | 통합 회귀 검증과 실행 문서 마무리 | server/ 단독 실행, 주요 흐름 E2E, 남은 목업 목록·제약 확인 |

테스트는 각 변경과 함께 추가·실행한다. 6번은 앞서 확인한 내용을 반복하는 단계가 아니라 기능 간 통합 경계를 검증하는 단계다. 고객 DB·GPU·실제 메일 호출은 하지 않는다.

현재까지의 커밋은 `92b6d2a`(결정·목업 목록), `d6e5e5c`(server 구조 병합), `02ca1df`(인증 백엔드), `8f5ec8b`(프론트 로그인·목업 안내), `5b3c19d`(인증된 실시간 분석 패널)다. 백엔드 인증·역할·seed 영속성·SSE 경계와 프론트 타입 검사·빌드는 QA에서 확인했다. 목록·상세·상태 API와 위젯·설정·관리자 API는 현재 명시적 목업 범위로 `docs/mock-inventory.md`에 기록한다.

## 커밋 기록과 남은 단계

아래 메시지는 커밋별 작업 범위를 설명하는 초안이며, 실제 확정 메시지는 Git 이력에서 확인한다. 추가 구현을 완료했다고 표시하지 않은 항목은 `docs/mock-inventory.md`의 교체 조건과 함께 추적한다.

### 1. 결정 기록

```text
docs(docs): 📝 KSJ HUJ 통합 기준과 목업 교체 목록 정리 (#1)

- 사용자 답변을 반영해 API 우선 연결과 로그인 전용 운영 범위를 명시
- 목업 위치와 데이터 출처, 대체할 API 및 제거 조건을 목록으로 관리
```

### 2. 이력 병합·배치·빌드

```text
build(infra): 📦 HUJ 코드를 서버 구조에 병합하고 빌드 경로 정리 (#1)

- KSJ 화면 구조를 유지하면서 HUJ 변경 이력을 병합하고 배포 코드를 server 아래 배치
- 충돌한 경로와 실행 설정을 정리하고 백엔드의 누락 사용자 타입을 보완
```

이 커밋은 `--no-commit` 병합에서 경로·구조 충돌을 해결한 두 부모 merge commit이다. 타입 정의는 기존 사용 코드에 맞추고 새 DB 모델을 도입하지 않았다. 인증과 프론트 로그인 연결은 각각 후속 커밋에서 완료했다.

### 3. 인증 백엔드

```text
feat(backend): ✨ 사전 생성 계정 로그인과 서버 권한 적용 (#1)

- 테스트 계정 초기화와 영구 저장 경로를 제공하고 반복 초기화 시 기존 계정을 덮어쓰지 않도록 처리
- 회원가입과 가입용 인증코드 API를 비활성화하고 로그인된 사용자와 역할에 따라 접근을 제한
- 인증 설정 누락을 명시적으로 처리하고 로그인 실행 경로에서 가입용 메일 의존성을 분리
```

테스트 계정은 환경변수 등 별도 입력으로 생성하고 비밀번호 평문·고정 인증값을 커밋하거나 출력하지 않는다. 비밀번호 해시는 기존 방식과 호환한다. 일반/관리자 테스트 역할을 구분한다.

### 4. 프론트 로그인·HTTP 연결

```text
feat(frontend): ✨ 로그인 기반 API 연결과 임시 목업 표시 적용 (#1)

- 모든 화면에 로그인 진입과 세션 복원 및 로그아웃 처리를 연결
- 구현된 API를 우선 사용하고 오류와 빈 응답을 목업 결과로 바꾸지 않도록 처리
- 미구현 기능의 목업을 별도로 표시하고 교체 목록과 연결
```

필요한 데이터 변환은 서비스 계층에서 처리한다. 목업 항목을 실제 서버의 상태 변경 API 등에 보내지 않는다. API를 호출하더라도 입력이 예시 데이터이거나 계산이 임시 룰이면 그 사실을 구분한다.

### 5. 실시간 분석 연결(구현 완료)

```text
feat(frontend): ✨ 실시간 분석 이벤트를 KSJ 화면 구조에 연결 (#1)

- 인증 정책에 맞는 SSE 연결과 이벤트 변환을 하나의 훅에서 관리
- 재연결 시 중복 수신과 로그아웃 및 화면 종료 시 연결을 정리
- 제공되지 않은 상세 필드를 명시하고 실제 이벤트에 목업 상세를 섞지 않도록 처리
```

인증 전달은 Bearer 요청 헤더를 사용하고 토큰을 URL에 넣지 않는다. `anomaly-stream.api.ts`가 fragmented SSE frame과 계약을 검증하며, `useRealtimeAnomalies`가 AbortController 정리·최대 3회 재연결·`eventId` 중복 제거를 담당한다. `RealtimeAnomalyPanel`은 KSJ 상세 목업과 분리되어 backend 계약 필드만 표시한다. QA는 stream 수동/스크립트 검증을 통과했으며 renderer 없는 React hook lifecycle 자동화는 실행하지 않고 source review로 제한했다.

### 6. 통합 검증·인수 문서(갱신 완료, 최종 커밋 대기)

```text
test(infra): ✅ 서버 단독 실행과 인증 분석 흐름 회귀 검증 추가 (#1)

- 로그인부터 API 조회와 실시간 수신까지 로컬 통합 검증을 추가
- 서버 폴더 단독 실행 절차와 API 경계 및 명시적 목업을 문서에 반영
```

## 이력·브랜치 처리

- 현재 이전 브랜치를 기준으로 진행하되, 실제 작업 전에 기존 Notion 연결 Issue·브랜치 유무를 확인한다. 임의 생성·이름 변경·삭제는 하지 않는다.
- 초기 이전·HUJ 통합 이력을 학교 저장소에도 보존하려면 해당 초기 PR은 일반 merge가 필요하다. Squash하면 기존 개별 커밋이 학교 기본 브랜치의 조상으로 보존되지 않는다. 실제 PR 생성·병합은 별도 단계다.
- 첨부 지침에 적힌 2026-1 저장소명·dev 대상은 현재 2026-2 저장소에 그대로 적용하지 않는다. 실제 대상 브랜치와 자동화 연결 상태를 확인한다.
- C1~C5는 구현·커밋되었고, C6 문서는 tracked-server 설치·빌드·통합 검증 결과를 반영한다. renderer 기반 React lifecycle 자동화는 별도 검증이 필요하며, 목록·상세·상태 API와 위젯·설정·관리자 API는 명시적 목업 범위로 남아 있다.
