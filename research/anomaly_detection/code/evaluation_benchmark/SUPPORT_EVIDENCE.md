# 시나리오 생성 표본 수와 통계적 근거

## 결론

기존 최소 30행은 검증된 충분 표본 수가 아니다. 소표본 제외를 위한 과거 휴리스틱이다.
지연은 정상 소요시간의 P95를 추정하지만 폭주·중단은 선언된 합성 요청 흐름을 조작한다.
따라서 필요한 참고 자료가 다르다. 폭주·중단의 원본 빈도가 충분히 관측됐다는 뜻은 아니다.
기존 평가 CSV, 모델, 생성 조건은 이 감사에서 변경하지 않는다.

## 30을 그대로 정당화할 수 없는 수학적 이유

정상 분포에서 독립·동일분포로 추출했다고 가정하면 참 P95보다 큰 값을 적어도 한 번 볼 확률은
`1 - 0.95**n`이다. 연속 분포 가정의 Wilks 단측 비모수 허용상한 논리와 대응한다.

| 독립 표본 수 | 상위 5%를 한 번 이상 관측할 확률 |
|---|---:|
| 30 | 78.54% |
| 59 | 95.15% |
| 100 | 99.41% |

59는 이 제한된 목적에서 계산된 최소 수다. **59개면 표본 P95가 정확하다는 뜻이 아니다.**
샘플 최댓값을 단측 허용상한으로 쓰는 문제와 표본 P95 자체의 정확도를 혼동하면 안 된다.
이항분포 순서통계량으로 만든 동등 꼬리 95% P95 신뢰구간은 n=30, 59에서 상한이 무한대이며,
n=72부터 양 끝이 유한해질 수 있다. 72 역시 좁은 구간이나 실무적 정확도를 보장하지 않는다.
개별 집단에 대한 설명이며, 모든 집단에 대한 동시 보장은 아니다.

실제 로그에는 의존성·시간 변화·동률이 있고, 이 원형 아카이브는 정상·하드룰 필터와 층화 표본
선정을 거쳤다. 따라서 위 IID 계산을 운영 로그에 대한 보장으로 주장하지 않는다.
복제 로그 수가 아니라 서로 다른 원본 실행 수를 세어야 한다.

## 실제 자료에서 확인하는 방법

`support_evidence.py`는 선별 원형 아카이브만 읽는다. 학습 모델이나 이상 정답은 사용하지 않는다.

- Adapter별 원형 행 수·서로 다른 원본 실행 수·기존 지연 생성 가능 여부 전수 집계
- 정확히 같은 Adapter/Process/totalCount에서 원본 실행이 200개 이상인 집단만 민감도 분석
- 원본 실행 단위 무작위 70/30 분할. 추출 풀과 확인 풀 분리
- 10·30·59·72·100개를 비복원 추출, 각 200회 반복, 기존과 같은 선형 보간 P95 사용
- 추출 풀 전체 P95 대비 오차와 별도 확인 풀의 초과 비율 계산
- 집단별 결과와 동일 집단 가중 중앙값 저장. 운영 P95의 정답을 안다고 주장하지 않음

실행 결과는 `reports/benchmark_support_evidence_20261023/summary.json`이다.
고정 30행이 충분하다는 사후 정당화가 아니라, 불확실성과 지원 범위를 드러내는 감사다.

### 실행한 민감도 분석 결과

조건을 만족한 정확 집단은 11개다. 모든 집단·각 표본 수에서 200회씩 반복했다.
아래 오차는 추출 풀 전체의 P95와 비교한 상대 오차이며, 실제 모집단 P95에 대한 오차는 아니다.
첫 열의 오차는 각 집단 반복 오차 중앙값들의 중앙값이고, 두 번째는 각 집단 반복 오차의
95분위수들을 다시 중앙값으로 요약한 것이다. 따라서 전체 집단에 대한 보장이나 최악값이 아니다.

| 표본 수 | 집단별 중앙 오차의 중앙값 | 집단별 P95 오차의 중앙값 |
|---|---:|---:|
| 30 | 5.31% | 23.10% |
| 59 | 4.21% | 16.53% |
| 100 | 3.68% | 10.03% |

30을 충분 표본 수라고 일반화할 수 없고, 59나 100도 오차를 없애지는 않는다.
새 Adapter 6종의 원형은 2~9행뿐이라 이 11개 집단 분석으로 그들의 지연 성능을 주장하지 않는다.

## 폭주·중단에는 왜 30행 제한이 없었나

현재 생성기는 14일, 20,160개의 분 단위 합성 요청 수를 별도로 만든다.
시간대·평일/주말 48개 층의 참고 분 수는 각각 240 또는 600개다.
이는 Adapter별 실제 운영 빈도 자료가 아니라, 상한 4건의 합성 Poisson 요청 수다.

| 시나리오 | 필요한 생성 재료 | 현재 조작 |
|---|---|---|
| 지연 3종 | 조건부 정상 소요시간 분포, 하드룰 상한까지의 여유 | P95 초과 지연 또는 시간에 따른 증가 |
| 시간대 폭주 | 유효한 원본 실행 1개 이상, 합성 정상 요청 흐름 | 대상 구간에 실행 복제 추가 |
| 입력 중단 | 유효한 원본 실행 1개 이상, 합성 정상 요청 흐름 | 대상 구간의 전체 실행 삭제 |

폭주·중단은 Adapter별 실제 도착 간격이나 요청 수 P95를 추정하지 않으므로 같은 소요시간
표본 조건이 필요하지 않았다. 대신 **합성 빈도에 대한 탐지 성능**이라는 가정이 붙는다.
2행을 수천 번 복제해도 독립 원본 표본 수가 증가하지 않으며, 실제 운영 다양성도 입증하지 않는다.
진짜 운영에서는 수집 정상 여부·활성 시간표·시간대별 유효 관측 구간·정상 공백 분포를
따로 검증해야 한다. 비정기 실행의 정상 공백과 장애를 같은 0건으로 취급해서는 안 된다.

## 후속 정책: 아직 활성화하지 않음

- 기존 30행을 논문상 충분 표본 수로 발표하지 않기
- 원본 실행 단위 지원 수와 분위수 신뢰구간을 집단별로 함께 표시
- 59를 쓴다면 단측 95/95 꼬리 관측의 최소 점검값으로만 명명
- 지연 주입 전 분위수 불확실성과 고정 하드룰 상한 사이의 실제 여유 확인
- 표본이 부족하면 더 넓은 참조를 사용했다는 사실 또는 해당 평가 미지원 명시
- 폭주·중단의 합성 정상 빈도 가정을 유지하되 운영 검증과 명확히 구분

통계적 의미가 있는 지연 생성의 대안은 표본 P95 자체가 아니라 **모집단 P95의 단측 95%
상한보다 큰 지연**을 주입하는 것이다. 연속 IID 가정에서 `k = binom.ppf(0.95, n, 0.95)+1`
번째 순서통계량을 그 상한으로 사용할 수 있다. k>n이면 유한한 상한을 만들 수 없어 미지원으로
표시한다. 이 때문에 최소 59가 도출되며, 이후에도 그 상한과 하드룰 상한 사이에 지연을
주입할 여유가 있어야 한다. 이 방법은 문서에 제안했을 뿐, 활성 생성기에 소급 적용하지 않았다.

## 참고문헌과 적용 범위

1. S. S. Wilks (1941), *Determination of Sample Sizes for Setting Tolerance Limits*,
   Annals of Mathematical Statistics 12(1), 91–96.
   https://doi.org/10.1214/aoms/1177731788
   단측 비모수 허용상한의 표본 수 논리. 우리 자료의 IID나 30행을 정당화하는 인용이 아니다.
2. R. J. Hyndman, Y. Fan (1996), *Sample Quantiles in Statistical Packages*,
   The American Statistician 50(4), 361–365.
   https://robjhyndman.com/publications/quantiles/
   분위수 계산 정의를 명시하는 근거. 원 생성기의 선형 보간을 그대로 사용하며,
   이 논문이 최소 30행 또는 59행을 권고한다고 주장하지 않는다.
