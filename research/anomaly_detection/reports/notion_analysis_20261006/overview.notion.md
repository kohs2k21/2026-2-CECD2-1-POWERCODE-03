## 4. 구현 시 고정할 기본 원칙

1. **단위와 키 분리:** 거래는 기간+거래 ID, Process 실행은 여기에 프로세스 ID+재시도를 추가합니다. 거래 ID는 모델 입력에서 제외하고 추적·결합 키로 사용합니다.

2. **결측과 미관측 유지:** 종료시각 없음·수집 공백·비교 불가를 정상 0점으로 바꾸지 않습니다. 모델 결측 대치 값은 학습 구간에서만 정하고 원래 결측 표시를 남깁니다.

3. **시간 누출 방지:** 모든 업무 기준선·희귀도·시퀀스 빈도·대치·스케일링·PCA는 학습 또는 해당 시점 이전 데이터만 사용합니다. 전체 기간 EDA 결과를 시험 모델 피처로 재사용하지 않습니다.

4. **상태와 정답 구분:** 현재 행동 모델에서 status·responseCode·성공/오류 건수·정합성 후보는 사후 근거로 사용합니다. 운영 상태의 실제 의미를 확인하기 전 실패 라벨로 합치지 않습니다.

5. **수치 변환과 품질 분리:** 양의 처리시간·건수에는 log1p, 음수가 가능한 오버헤드에는 부호 보존 로그 변환을 사용합니다. 시각 오류·불완전한 집계는 변환 전에 감사하고 신뢰도를 표시합니다.

6. **후보를 사건으로 묶기:** 거래별 단계 후보를 한 사건으로 묶고 연속 시간창 경보를 집계합니다. 행 수와 고유 거래/사건 수를 함께 보고하며 세 모델 후보 수를 단순 합산하지 않습니다.

시간을 섞는 무작위 분할 대신 시간 전진 검증을 유지합니다. 현재 데이터는 첫 기간 중심 학습이고 후속 기간은 새 업무가 많으므로 **기존 업무의 미래 성능**과 **신규 업무/환경으로의 전이 성능**을 나누어 보고합니다. 새 환경 적응 실험도 적응용 과거 구간과 미래 시험 구간을 다시 분리합니다.

경보 기준은 검증 데이터에서 정하고 시험 데이터에서는 고정합니다. 같은 검토량 또는 실제 장애 라벨의 목표 precision/recall로 모델을 비교하며, 시점·업무별 임계값은 검증 후 선택합니다. 후보의 교집합을 합의로 쓰더라도 모델들은 같은 로그를 공유하므로 독립된 세 증거라고 가정하지 않습니다.

최소 평가 지표: 실제 검토 라벨 precision/recall/F1, 정상·이상 후보 검토 표본 수와 추출 기준, 기간/업무별 성능, 일당 고유 사건 경보 수, 탐지 지연, 비교 가능 구간 비율, 실행 시간·메모리. 양성 후보만 검토하면 놓친 이상을 알 수 없으므로 비후보와 신규 업무도 층화 검토합니다.

## 8. 추가로 필요한 운영 정보와 데이터

- status/responseCode 사전, 부분 성공·복구·보상·동기/비동기 실행 정의, 어댑터별 처리 건수 단위.

- 수집기 heartbeat·수집 시작/중단 시각·지연 도착 정책·보존 범위·시계 동기화 상태.

- 테스트/운영 구분, 배포·설정 변경·업무 버전·스케줄·부하 시험 메타데이터. TEST라는 ID만으로 확정하지 않습니다.

- 실제 재시도 로그, 사람 검토로 확정된 정상/이상 사례, 통제된 장애 주입 이력과 사건 시간.

- 메시지 본문 기반 의미 이상은 현재 세 노트북의 구조화 로그 분석 범위 밖입니다. 해당 모델을 추가하려면 본문 접근·민감정보 처리·수집 범위를 별도로 확인해야 합니다.

## 9. 구현 우선순위와 경보 설명 형식

1. 스키마·실행 키·수집 상태·완료 커버리지 점검과 데이터 계약을 먼저 확정합니다.

2. 현재 IF 기준 모델을 재현하고 시간 분리·학습 전용 전처리·고정 시험 임계값을 유지합니다.

3. 업무별 지연 기준선과 신규 업무 경로, 미완료 경과시간 감시를 추가합니다.

4. 구조·의존·시퀀스·시간창 피처를 각각 추가하며 동일 평가 조건으로 ablation합니다.

5. 실제 라벨과 운영 검토량으로 모델·임계값을 선택하고 사건 단위 경보와 drift 감시를 운영합니다.
