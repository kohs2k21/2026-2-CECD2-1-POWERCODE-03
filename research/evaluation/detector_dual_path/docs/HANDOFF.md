# 운영 이식 전 합의 항목 (#45)

- 현재 결과: 연구 재생·합성 비교·로컬 경합 시험; 운영 Detector·DB·API 변경 제외
- 두 입력 경로: PROCESS 실시간 / TIME_WINDOW 주기적 추세
- 세 운영 모드: Rule only / ML only / Rule+ML 병렬; 입력 경로 구분과 별개
- 경로 탐지의 합집합: 추가 탐지 효과 계산용; 운영 알림·심각도 정책의 확정 근거 아님
- 두 입력 경로 분리와 두 ML 모델 필수성 구분; 추세 ML은 무유입 Rule·통계적 기준과 비교 전 운영 채택 미확정

| 담당 | 후속 계약 |
|---|---|
| ERD | 결과의 입력 단위, PROCESS revision 키, 시간창 scope·[start,end)·설정 버전 키 구분 |
| Collector | event time / observed time, retry / revision / 재전달 구분; BODY 대기와 기본 판정 분리 |
| Trainer | PROCESS·시간창별 모델/전처리·정규화·임계값·학습 참조를 함께 manifest 고정 |
| Detector | 두 경로 독립 스케줄; 확정 결과 불변; 모델 미준비·timeout·부분 판정 별도 상태 |
| Backend/WebUI | 입력 단위·버전·가용성·지연 구분; 추세 결과의 PROCESS 판정 덮어쓰기 금지 |
| XAI | 사용 모델·입력 단위·Rule 근거 구분; 기여도를 확정 원인으로 표현 금지 |

- 창/주기 변경: 피처 분포·정상 참조·모델·정규화·임계값 재적합 후 별도 후보 버전
- 1분 창의 기존 5분 보조 피처: 최소 5분 자료 필요; 운영 준비 기준과 표시 일치
- 원본 자료 확보 후: 정상 시간대/요일·업무별 지원 범위 확인, 동일 사건·정상 감시시간으로 재평가
- count 계약 위반: 기존 ML 피처만으로 충분한지 확인; 논리 Rule의 별도 기준 비교 필요
- 부하 재시험: 실제 큐·PostgreSQL·고객 API 공개 지연·SSE 포함; ESB 발생→최종 판정 시각 측정
- 자원 비교 기준: 실시간 실행 슬롯 수 고정·추세 운영 주기 일치; 현재 100Hz 시험의 슬롯 배분 차이와 분리
- 운영 채택: 오경보/추가 탐지/자원/지연 허용 기준 합의 후 최종 결정
