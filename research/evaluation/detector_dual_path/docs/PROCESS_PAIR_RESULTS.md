## 결과 해석·다음 구현 제안

- **탐지 정책:** Rule·ML 둘 다 판정하고 결과 합침 유지 제안. 이번 순서 실행에서도 Rule에 걸린 입력의 ML을 생략하지 않았으므로 Rule 필터 뒤 ML 실행 정책과 구분
- **실행 방식:** 현재 간단한 Rule·CPU1·합성 IF에서는 물리적 동시 실행의 일관된 이득 확인 불가. 작은 순서 실행기를 초기 기준선으로 두고, 복잡한 Rule·실제 PROCESS 모델·다중 코어 조건이 생기면 재측정 제안
- **병행 감시:** 기존 실시간 PROCESS 탐지와 독립 시간창 Rule의 병행 추천에 대한 반증은 아님. 이번 시험은 한 PROCESS 내부 Rule/ML 실행 방식 비교이며, 시간창 Rule은 두 방식에서 같은 배경 작업
- **병목 개선:** 동시 실행 전 공통 전처리 비용·배치/벡터화·실제 동시 처리 수·큐 적체 관리 검토 우선. 현재 운영 구조·기본 모드 변경은 사용자 결과 검토 후 결정
- **팀원 모델:** v12는 시간창·문맥 모델로 별도 평가·연동. PROCESS 모델이 필요하면 해당 단위의 피처/모델 산출물 합의 필요; 입력 단위 변경만으로 재사용 금지
- **장애 독립성:** 운영 구현에서는 Rule 입력 준비와 ML encoder/모델 준비 분리 필요. 준비 단계 실패 시 Rule을 유지하는 실제 fallback은 이번 성능 실험에서 구현·검증하지 않음
