# Rule generator v0.1 평가 결과

[demo.html](demo.html)을 로컬 브라우저에서 열면 피처 64개와 판단 32개, 원문·근거·최초/수정 이력을 확인할 수 있다. HTML에는 데이터가 내장돼 있으며 외부 CDN·fetch·서버가 필요 없다. GitHub 파일 화면은 HTML을 실행하지 않으므로 로컬에 내려받아 연다.

| 결과 | 개수 |
|---|---:|
| 모델 생성 HR 승인 | 5 |
| 모델 생성 SR 승인 | 15 |
| 조건 보존 보류 | 1 |
| 근거 요청 | 5 |
| 적용 불가 | 5 |
| 최종 실패 | 1 |
| 수동 예제 | 0 |

승인된 규칙은 20개이며 피처 17개를 참조한다. 판단 31/32 승인은 보류·근거 요청·적용 불가를 포함한 개발 결과다. 기존 32개 평가 입력을 다시 사용했고, 실제 v2 SYSTEM과 전체 계약을 제공한 후 최초 28개·수정 3개가 승인됐다. 추가 SFT 없이 안내문 연결을 수정한 결과이며 독립 성능 개선으로 해석하지 않는다.

- `feature_catalog.json`: 정의·측정 64개, 새 모델 발굴 수 아님
- `example_inputs.jsonl`, `examples/`: 정답을 포함하지 않는 고정 집계 입력
- `model_outputs.jsonl`: 최초32/수정4 모델 원문과 검증
- `validated_rules.json`: 승인 HR/SR20개
- `pending_decisions.json`: 보류·요청·적용 불가11개
- `failed_outputs.jsonl`: 숫자 합계/Boolean 진단 설명 혼동1개
- `human_reviews.json`: 응답 SHA에 연결된 직접 의미 검토36개
- `summary.json`: 규칙·판단·실패 개수
- `publication_provenance.json`: 공개 복사 과정과 원본/공개 SHA
- `rule_utility_review.json`: 조건 발동 가능성과 오프라인 범위의 후속 검토

원본 CSV/SQL·행별 데이터·거래 ID는 포함하지 않았다. 입력에는 스키마 이름과 집계 측정·기간이 있으며 원본 파일 경로를 제거했다. 모델 출력 원문·통계·계산식·원천 버전은 유지했다. 원본 파일을 통한 관계·원천 재검증과 전체 재학습은 이 공개 자료만으로 재현할 수 없다. 기록 조회·검증은 CPU로 가능하고, 새 모델 생성에는 별도 로컬 Base와 할당 GPU가 필요하다.

검증기의 계약 통과는 규칙의 진단 효용이나 운영 승인을 뜻하지 않는다. 비율 피처 두 개의 `gt p95=1` 조건은 유효 범위에서 발동 불가하며 상태 빈도는 실시간 시간창 정책이 필요하다. 실제 이상탐지 결과나 장애 탐지율은 제공하지 않는다.
