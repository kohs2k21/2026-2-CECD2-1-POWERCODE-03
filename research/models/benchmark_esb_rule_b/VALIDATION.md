# 검증 범위

이 전달은 선택된 B 가중치와 기존 native 검증기를 보존하고 서비스 초안 변환 경로를 추가한다. 새 SFT·ML fit·임계값 보정·GPU 생성·합성 데이터 재생성은 수행하지 않는다. 이번 실제 CPU 결과는 `validation.json`을 따른다.

전달 코드 CPU 26/26, 기존 baseline 회귀 14/14, 공개 PFS 실제 저장 응답 8/8을 확인했다. 원본 ESB 저장 응답 522개는 기존과 동일하게 510개 통과·12개 실패였으며, 통과·실패가 바뀐 사례는 없었다. baseline 초안 변환 214회는 겹치는 평가 사례의 제안 횟수이며 독립 운영 규칙 개수가 아니다.

## 새 전달 코드 검사

- 공개 실제 PFS B 응답 8개: 입력 SHA 확인 → native 검증 → baseline 초안 변환
- 수치 경계 strict gt, 결측·비수치·NaN·무한대·Boolean의 평가 불가 처리
- 피처 SHA·단위·모집단·TRAIN 참조·조건·근거 바인딩, 잘못된 버전·중복 역할·누락 역할 차단
- 기존 TRAIN 입력 생성 코드와 새 native 입력 연결, 거래·시각 분할 유지
- 최대 1회 수정, 최초 실패 보존, 잘린 응답 거부, 코드 정답 대체 없음
- 원본 함수 5개(RULE_SYSTEM 포함)의 변형 없는 추출 및 SHA 출처 기록
- 선택 가중치 SHA, 공개 config의 Base 경로 문자열만 변경, 기존 가중치 불변

합성 제어 시험과 mocked 생성기는 모델 성능 분모에 합산하지 않는다. `evaluate_draft`는 연구용 스칼라 실행 검사이며 서비스의 DB·큐·API·XAI 통합 시험과 구분한다. 실제 GPU 생성은 과거 기록을 참조하며 이번 전달 추론기에서 새로 실행하지 않았다.

## 과거 실제 모델 평가

| 범위 | A | B | 해석 |
|---|---:|---:|---|
| 원본 ESB TEST 전체 검사, 수정 최대 1회 | 513/522 | 510/522 | silver 명세 재현; 확정 장애 탐지 정확도 아님 |
| 공개 PFS 피처별 3역할 응답 | 8/8 | 8/8 | 두 모델의 유효 수치 SR 판정 동일 |
| IoT-23 피처별 3역할 응답 | 8/8 | 7/8 | B의 duration 묶음은 잘못된 상한 주장으로 실패 유지 |

PFS 수치 SR은 경고 23,054 / TP 8,540 / precision 37.04% / recall 51.79% / F1 43.19%, 평가 불가 29,317개였다. 관측 결측 진단을 합치면 precision 16.32%로 내려갔으므로 이번 baseline 서비스 converter는 관측 진단을 자동 활성화하지 않는다. 이는 기존 결과의 해석이며 임계값을 다시 조정한 결과가 아니다.

기존 AE SR·수치 SR·ML의 ESB 재현(59피처, TEST 46,815거래)은 경고 892 / 비경고 44,929 / 평가 불가 994로 별도 진행됐다. **해당 탐지 경로에 B 생성물을 넣은 결과가 아니다.** 이 전달이 기존 탐지 성능을 개선했다는 근거로 사용할 수 없다.

## 남은 한계

- B가 A보다 우수하다는 근거 미확인; B 선택은 전달할 연구 후보 지정
- ESB 교사는 AI 작성·코드 검증 자료, 기업 담당자의 실제 장애·업무 계약 판정과 구분
- PFS·IoT 및 ESB 평가 자료는 이전 개발에서 확인한 자료; 미사용 독립 최종 시험으로 주장하지 않음
- arbitrary multi-feature logical rule 발굴·AE 의사 라벨 규칙 생성·물리적 장애 원인 확정은 이 B provider의 범위 밖
- 새로운 서비스 provider 등록, 관리자 채택, Detector evidence-v4 및 XAI E2E 미실행
- 원격 CI 상태는 PR의 실제 실행 결과로 별도 확인; 로컬 CPU 검사를 원격 CI 통과로 표시하지 않음
