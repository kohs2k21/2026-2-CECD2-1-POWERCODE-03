# 실제 실행과 적용 범위

공식 CLI·선택 모델·계약을 갖춘 로컬 명세 패키지이다. 최종 실행 정책은 delivery-final-frozen1.4이다. Feature는 기존 silver51 LoRA, Rule은 고정 LoRA이며 이 단계의 추가 학습은0회다. Base/어댑터/계약 SHA는 model_manifest와 artifact_manifest를 확인한다.

서로 다른 정책의 최초 성적을 합산하지 않는다.

## 실제 모델 수정

공개 관계 합계의 is_missing 진단은 유지4행·숫자유효2행이다. 같은 최초 입력/원문 SHA에서 전체 근거 재전달 수정은 잘못된 “2 usable observations”를 반복했다. 실패 필드와 조건/값/참조 통계만 전달한825토큰 수정에서는 실제 모델이 “4 evaluable observations”로 수정했다. 기존 수정 입력은2985토큰, 최초 입력은4237토큰이다. 코드가 문장을 대신 쓰지 않았다.

실자료 자식 개수의 수치 규칙은 gt1인데 설명이 “Under is_missing ... unassessed”였다. 공통 연산자-조건 검사로 이를 검출했고, 실제 모델이 gt 조건·51590 평가행·현재 unassessed0을 설명하도록 수정했다. 임계값·상태·측정·기준선 ID는 바뀌지 않았다. 유효한 비교 설명과 선택행0 문맥을 잘못 거절하지 않는 대조도 검사했다.

## 선택과 계산 계약

이번 동일 입력·토큰·문법·NF4/BF16·greedy/thinkingFalse 비교에서 양성5개 계산은 Base/Feature51 모두5/5, 완결된 근거 내 설명은4/5 대5/5였다. 별도 적절한 보류는 Base최초0/1→수정1/1, Feature51최초1/1이다. 기존51건 어댑터를 기본값으로 선택한 근거이며 새 학습 효과가 아니다. 원래 Oct26 정책의 계산3/5·4/5, 직접 의미 승인2/5·3/5 점수는 그대로 보존한다.

feature5.2의 result_use는 value/unavailable/unavailable_or_zero를 모델이 고른다. 코드는 그 공통 연산을 그대로 컴파일한다. strict nullable OR는 바꾸지 않았다. 명시적 null 분기는 일반 bottom-type 규칙으로 숫자/Boolean과 안전하게 결합하며 부적절한 혼합은 거절한다. E02 평균은[3,null,null,null], 빈 자식은 평균0이 아니다. E05 중첩 비교 가용성은5행 모두 Boolean이며3true·2false다.

## 최종 선별 수

실제 생성·측정한 활성 정의는 실자료6·통제7이다. 기존 계산 재현/사용 검증이며 새로운 정보 발견 수로 세지 않는다. 실제 선별 역할은{'observed': 9, 'baseline': 2, 'hr': 2}이다. 피처·조건 단위 고유 기록은13개, 숫자 비율 is_missing 경로와 직접 가용성 Boolean의 동일 사건을 정리하면11개다. 원천·행·모집단이 다른 정의를 임의로 합치지 않는다. 보류/근거 요청은{'request_evidence': 1, 'no_candidate_review': 1}이며 규칙 생성 수에 포함하지 않는다.

원래63개(파생56·원시7)·74역할(HR3·관측35·수치36)은 보존한다. 부속 정의를 원천/계산으로 정리한70개는70/70 재측정·독립 계산, 유효 관측61·선택행0인7·유지행 전부unavailable인2다. 변동42·상수19·관측 없는9를 구분한다. 원래74역할은 원래 근거·원천에 남겨 두며 새 source에 조용히 재라벨링하지 않는다. 고객 전체 정의·원천값·민감 프롬프트는 공개 패키지에서 제외한다.

실자료 비율 적용51596행 중 숫자유효51541·unavailable55이다. 숫자 is_missing 진단과 직접 Boolean 진단이 같은55행을 가리킨다. 별도 TRAIN 참조134903유효값의 p95는1ratio이며 gt1 비교는현재51541행 평가·55행unassessed·발동0이다. 거래별 프로세스 수는TRAIN134841값의 p95=1count와 비교해현재51590행 중7행에서gt1이 성립했다. 이는 명세 검증 통계이며 장애7건이 아니다. 현재5행·참조0행인 그룹은비교를 만들지 않고참조최소20표본의근거를요청했다.

## 설명 권한과 제한

공식 계산 사실은 compiler 작성이며 not_AI_generated=true이다. AI 원문·코드 사실·자동 설명 검사·실제 모델 수정·사후 검토를 구분한다. 프로그램은 자유 문장 전체 승인 권한이 없으며 free_prose_approval=not_granted_by_program_supported_claims_only이다. 현재 관측에 관한 좁은 계산 설명과 미래/온라인 보장·업무 의미는 별개이다. 일부 포괄적인 미래 가용성 문구는 공식 계산 동작의 정의로 사용하지 않는다.

Rule 교사 오류2건의 과거 학습 노출은 남아 있다. 현재 검증 통과가 그 이력을 지우지 않는다. 원시 코드 의미·업무 SLA·정상성·장애 라벨을 발명하지 않는다. parent 속성 조회·임의 스키마 보장·자동 그룹 fallback·현재p95의과거승격·온라인/운영 승인은지원하지않는다. 참조없는그룹의request_evidence와unavailable을정상0/false로채우지않는다.

공개 실제 생성 원문은 examples/generated/public_delivery에 있다. 서버 GPU 진단만 publication receipt로 명시해 제외했고 원본 Model 입력·응답 bytes는 유지했다. 공개 예시의 수치 SR에 가짜 과거기준선을만들지않았으며 reference API의실제수치SR은승인실로그에서검증했다. Base와민감자료는배포하지않는다. 다른위치복사본의공식Model실행및CPU재생을확인했다.

이것은현재지원범위의기능제출본이며모든새입력의완벽함을뜻하지않는다. IF·실제이상탐지·추가SFT·Git stage/commit/push/PR/merge는실행하지않았다.
