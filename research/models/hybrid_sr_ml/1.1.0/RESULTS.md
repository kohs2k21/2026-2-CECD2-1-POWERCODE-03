# 실제 실행 결과: 모델 번들1.1

새 탐지 명령의 기본값은 `--ratio-policy fallback`이다. 분모0인 비율을 제외하지 않고 바인딩된 대체 계산·조건을 실제로 검사한다. 원래 비율을0으로 채우지 않으며 기존 ML입력과 가중치는 그대로다. `--ratio-policy strict`는 이전 엄격한 비교를 실행한다.

## 대체 평가의 근거

- 12개 비율 분기는 기존 건수 차이 피처10종의 정확한 정의·단위·모집단·TRAIN 기준선을 재사용한다. 예: P전체/P상태N → P전체−P상태N > 기존p95.
- 전체 건수가0인 성공/실패 비율2개는 제공된 PROCESS 컬럼 설명의 전체=성공+실패를 실제 검사하는 SR 분기다. 다른4개 P계수 비율 분기에도 이 원천 일관성 검사를 먼저 적용한다.
- 이 관계는 사용자가 제공한 컬럼 설명 이미지의 내용이며 DB가 강제한다는 근거와 실제 장애 라벨은 없다. 새 SR 일관성 검토로 기록하고 HR은 바꾸지 않았다.
- 분자·분모 또는 필요한 제3의 카운트가 결측·음수·비유한이면 대체 판정을 만들어내지 않는다. 대체 피처나 기준선이 불명확해도 보류한다.
- `profiles/esb/ratio_fallback.json`은14개 분기의 원래/대체 명세·원천·모집단·기준선과 바인딩SHA를 기록한다.
- `ratio_fallback/alternative_rule_evidence.csv.gz`는 거래/원천행·비율규칙·분자/분모·실제 대체 규칙·대체 값/조건·판정 이유를 보존한다. `decisions.csv.gz`에 엄격한 기존 판정도 함께 있다.

## 검증

- 원천65개 피처 전체 값·모집단·선택불가 마스크와 모델9개 점수/판정, 논리 SR 전체 predicate와 판정이 기존 실행과 같았다. 실제 대조34개 통과, 실패0개다.
- 경계·바인딩·원천 키 검증29개, 기존 OR·C3 동작 검사10개, 대체 실행 실패·strict 경로 검사4개가 통과했다. 이들은 기능 검사이며 모델 정확도로 합산하지 않는다.
- 별도 디렉터리에 복사한 번들에서 공개 CSV32거래 생성→캡처→피처→대체 SR/ML/논리 SR 탐지, CPU검사, TEST 학습 거부 등6개 명령 검사가 통과했다. 학습0회다.
- FlowBench 두 프로필의 동일한 기존 component 전체 결과를 새 결합 코드에 다시 적용해 모든 집계와 기여가 같음을 확인했다. 새 모델추론이나 새로운 독립평가는 아니다. ESB count 전용 대체 정책을 FlowBench 원천 시간 결측에 적용하지 않는다.
- 기존 번들517개 파일은 그대로다. ML15개와 LoRA5개 파일 바이트도 그대로이며 새 설치·Qwen/SFT·ML학습·기준선 재보정·GitHub push는0회다.
- 실제 ESB 전체 실행122.002초. 새 원천 피처·모델 추론·논리/대체 평가와 기록을 포함한 배치 시간이며 실시간 거래당 지연은 아니다.

## 해석 범위

이 결과는 이미 분석했던 ESB TEST의 후속 명세·실행 정책 비교다. 기업에서 확정한 장애 정답이 없어 운영 precision/recall과 정상률을 주장하지 않는다. 대체 검사12개가 기존 활성 검사와 겹치므로 새로운 탐지 성능 우위를 입증하지 않는다.
이 번들은 연구 실행용이며 서비스 API·DB·알림의 운영 배포를 수행하지 않았다. 기존 Trainer와 선택적 명세 생성 명령은 보존했다. BASE 가중치·가상환경·고객 CSV는 압축본에 포함하지 않는다.
초기 실행의 반복 NPZ 읽기 병목은 파일당1회 로딩으로 수정했다. 중단된 실행은 verification/esb_actual에, 완주한 실제 결과는 verification/esb_actual_completed에 분리 보존했다.
