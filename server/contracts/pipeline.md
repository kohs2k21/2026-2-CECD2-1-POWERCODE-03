# 저장·추천·학습·탐지 흐름

```text
CSV/향후 ESB API → Collector → 허용 필드 원천 저장 ┬→ 기간 스냅샷 → 변수 생성 모델 → 변수셋 버전 → 기간 전체 정제
                                                   │                                      ↓
                                                   │                           Rule 추천 모델 → 초안 채택
                                                   │                                      ↓
                                                   └→ 변수 큐(승인 구성 대기)     수동 IF 학습 → 검증 평가 → 관리자 적용
                                                                 ↓                            ↓
                                                          Feature worker → 탐지 큐 → Detector(Rule+IF) → 판정 DB
```

원천은 BODY·인증정보를 투영에서 제외하고 저장한다. CSV 재생은 프로토타입이며 원천 ESB API 수집 계약은 아직 없다. 수집은 학습 실행 여부와 무관하게 지속된다. 저장된 기간을 사용자가 지정할 때만 변수 생성·Rule 추천·IF 학습 작업을 등록한다. 학습 성공은 후보일 뿐이며 수동 라벨이 있는 고정 validation 평가와 관리자 적용 요청을 통과해야 한다. 운영에서는 현재 승인된 변수셋·Rule·모델 버전만 사용한다.

Express의 기존 JWT/JSON 계정 체계를 유지한다. `/api/jobs`는 작업 등록·이력·추천 Rule 채택, `/api/configurations`는 활성 구성·적용·복원, `/api/pipeline`은 출처·라벨·판정·측정치 조회를 제공한다. 작업과 관측의 영속 메시지는 `queues.md`를 따른다. 실제 모델 함수 형식은 `model_adapters.md`를 따른다.

## 현재 구현의 경계

- 파생변수는 P의 검증된 수치 필드, 제한된 산술 DSL과 feature_v5의 Process 행 AST를 지원한다. 추천 모델의 출력은 자동으로 해당 기간 전체에 적용되고 사용자가 변수마다 선택하는 단계는 없다.
- 추천 Rule은 사용자 채택 후 불변 초안 버전이 된다. `F.*` 조건은 고정된 변수셋과 연결되고, 학습·운영 구성의 변수셋이 같아야 한다.
- IF 학습·파일/fit 검증·점수 계산을 구현했다. 새 파생변수는 새 IF를 학습하고 기존 v12 가중치의 입력을 변경하지 않는다.
- 평가는 고정 validation/test에서 Rule·IF·OR 결합 지표를 계산한다. 라벨, IF 점수 또는 Rule 입력이 부족하면 `unmeasured`다. 결측률 변화는 재학습 검토 신호만 남기며 자동 재학습·자동 적용하지 않는다.
- 새 판정은 DB 조회 API로 볼 수 있다. 기존 데모 SSE는 이 DB 판정 스트림과 연결되지 않았다.
- 시간대가 확인되지 않은 원천 시각은 UTC 발생 시각으로 간주하지 않는다. T/M 부모 as-of 관계와 실제 ESB 키·revision은 후속 원천 계약 검증이 필요하다.

feature_v5/Rule v2의 실제 모델 생성은 별도 GPU 서비스로 수행한다. 최신 v12의 연속 1분 탐지는 window_worker가 저장 이력과 수집 완료 watermark로 수행한다. 상세 설정은 ../worker/DEPLOYMENT.md를 따른다.
